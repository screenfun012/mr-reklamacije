# @mr/i18n

Internationalization package for MR Reklamacije using Paraglide v2.

## Locales

- `sr` (Serbian, Latin script) — base locale
- `en` (English)

## Usage

```ts
import { m, setLocale, getLocale } from '@mr/i18n'

setLocale('sr')
console.log(m.nav_dashboard()) // "Kontrolna tabla"

setLocale('en')
console.log(m.action_save()) // "Save"
```

## Adding new messages

1. Add key to `src/messages/sr.json` (Serbian, primary — write first)
2. Add same key to `src/messages/en.json` (English translation)
3. Run `pnpm --filter @mr/i18n compile` (or `build`/`test` which auto-compile)
4. Use `m.your_new_key()` in consumers

## Naming convention

Per `.cursor/rules/09-i18n.mdc`, message keys follow:

```
<namespace>_<context>_<variant?>
```

Namespaces:

- `nav_*` — navigation, sidebar
- `action_*` — verbs (save, cancel, delete, export)
- `field_*` — form field labels
- `placeholder_*` — form placeholder text
- `validation_*` — form error messages
- `success_*` — success toasts
- `error_*` — error toasts
- `empty_*` — empty state copy
- `claim_*`, `emotive_*`, `domace_*`, `stats_*`, `admin_*`, `portal_*`, `auth_*`

Keys must be valid JS identifiers — no dots, no kebab-case. Use
`nav_dashboard`, not `nav.dashboard` or `nav-dashboard`.

## Layout

```
packages/i18n/
├── project.inlang/
│   └── settings.json          # Paraglide project config
├── src/
│   ├── messages/
│   │   ├── sr.json            # Source (Serbian, authoritative)
│   │   └── en.json            # Source (English)
│   ├── paraglide/             # Generated by `paraglide-js compile`
│   ├── __tests__/
│   └── index.ts               # Public API: m, setLocale, getLocale, locales, baseLocale
└── dist/                      # tsc output
```

`src/paraglide/` is auto-generated and excluded from lint. Do not edit.
